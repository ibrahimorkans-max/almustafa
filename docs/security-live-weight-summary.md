# Sign-in security, sessions, passkeys and live weight — summary

Branch `security-live-weight`. Previous work: [hr-phase-12-summary.md](hr-phase-12-summary.md), [access-security-summary.md](access-security-summary.md).

## Built
| Area | What exists |
|---|---|
| **Live weight** | **Gate & weighbridge → Live weight**, and above **Vehicles at gate**: each weighbridge's reading refreshed every second, in kg and maund, marked **Stable**, **Moving** or **No signal** (nothing for 5 seconds).<br>• The gate agent sends the indicator reading about once a second: `ricemill-agent live` (`POST /api/v1/gate/live-weight`, signed like every agent request, needs `weighment.capture`, a reading outside the scale's range is refused)<br>• Readings are kept in the cache only: display, never the books. A weight is still recorded only by the agent's stable capture with its photo and readings; a reading the server cannot take is dropped, never queued |
| **Sessions** | **Security → Sessions** for everyone (their own) and for holders of `session.view_all` (the whole mill):<br>• browser and system ("Chrome 141 on Windows 10/11"), sign-in by password or passkey, IP<br>• **location**: city, region and country from the IP (offline DB-IP City Lite database, nothing sent outside; "Mill network" for local addresses) and, when the person allows the browser's prompt, the browser's own position with its accuracy and a map link<br>• open sessions by default, or the full history including signed-out and expired ones<br>• **Sign out** one session, **Sign out all my other sessions**<br>• **Security → Failed sign-ins** (owner and auditors): wrong passwords and codes, unknown usernames, unrecognised passkeys, devices waiting for approval, blocked networks, lockdown, with the IP's city, last 90 days |
| **New sign-in alerts** | A sign-in from a device the account never used, or from a city not seen in 90 days, is reported to the person (in-app notification) and to the owner. The first sign-in of a new account is not reported |
| **Trusted devices** | **Security → Sign-in rules** (owner): new phones and computers must be approved before they can sign in, for **everyone**, **selected accounts** (switch on the account under Users) or **off**.<br>• A sign-in from a new device stops with a clear message and puts a request under **Approvals**; the owner (`device.manage`) approves it; nobody approves their own device; a Super Admin's device still needs another Super Admin<br>• Attendance-only employees are left out of "everyone": HR already approves their phone under Attendance devices<br>• The production template starts with `RICEMILL_TRUSTED_DEVICES=everyone` |
| **IP limits** | The IP allow-list under **Users → account** is now available for every account (not only Super Admins); an account with entries signs in only from those networks. A Super Admin's list is edited only by a Super Admin |
| **Passkeys** | User menu → **Passkeys**: add a passkey on the device (fingerprint, face or device PIN), see when each was last used, remove one.<br>• **Sign in with a passkey** on the sign-in page: no password, no 6-digit code; it counts as both factors. The same account checks apply (locked, suspended, lockdown, firm suspended, IP allow-list, trusted device)<br>• The private key never leaves the device and works only on this site's domain, so a copied database or a fake sign-in page cannot use it. Password and code remain as the fallback<br>• Standard WebAuthn through `spatie/laravel-passkeys` / `web-auth/webauthn-lib`; the browser side uses the browser's own API (`public/js/passkeys.js`), no build step |
| **Owner** | The Owner role holds every permission of the mill, including any added later, except creating other firms (`entity.manage`) and the two broker-only narrowing permissions. New `entity.edit_own`: the owner edits the mill's own name, NTN, STRN, address and phone (not its code or status). Maker-checker still applies: the owner never approves their own requests |

## Notes
* **Locally**, use `http://localhost:8000` (not `127.0.0.1`) for passkeys: browsers do not allow passkeys on an IP address. `RICEMILL_TRUSTED_DEVICES=off` in development.
* **Location database**: `php artisan geoip:update` (monthly on the 5th by the scheduler). DB-IP City Lite is CC BY 4.0; the sessions screen credits it.
* A browser's position is asked for once per tab after sign-in; refusing changes nothing except the map.
